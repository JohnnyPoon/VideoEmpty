CapCut export: calibrate shape/font scale against user-corrected reference

The user re-exported a real project, then manually resized 3 items inside
CapCut to what they actually wanted (kept as ".. - Copy"). Diffing the two
draft_content.json files produced concrete shape_size/font_size ratios:

  Step shape      713 x 167 -> 397 x 96    (~0.55 x 0.57)
  Comment shape   535 x  83 -> 466 x 62    (~0.87 x 0.74)
  Comment shape   535 x  83 -> 400 x 50    (~0.75 x 0.60)
  Step "1."       font 7.0  -> 6.0         (0.857)
  Step "Iter 9"   font 6.6  -> 5.6         (0.848)
  Comment row 2   font 5.2  -> 5.0         (0.961)
  border_width    visibly thinner across all items

The animations (Left Slide-In, 300ms In) and per-segment position were
unchanged; only sizes needed correction. Per-element variance is the user
fine-tuning individual items, not a systemic mismatch.

Introduce two export-time multipliers on CapCutExportOptions:

  ShapeScale = 0.65  (midpoint between Step 0.56 and Comment 0.75)
  FontScale  = 0.85  (midpoint between Step 0.85 and Comment 0.96)

Applied to shape_size, custom_points (via halved pxW/pxH), border_width,
fixed_width (so the text wrap box tracks the shape it sits on), font_size
and style.size. The in-app preview is untouched -- only the CapCut emit
shrinks, matching what the user actually keeps after manual cleanup.

Defaults flow through the existing UI (MainWindow.ExportToCapCut) so users
get the corrected sizes on the next export with no UI work; the parameters
remain tunable for power users that want different proportions.
